# Nexus Store: Telegram-магазин и админ-панель

Рабочий каркас бота на `aiogram 3`. Уже реализованы:

- команда `/menu` и главное меню с обложкой;
- каталог с категориями ChatGPT, Claude, Gemini, Notion, Grok, Perplexity, Netflix, Duolingo и CapCut;
- кошелёк с быстрыми суммами и вводом своей суммы;
- экраны бонуса, профиля, техподдержки и «прочее»;
- обложки из папки `brand-covers` в соответствующих разделах;
- закрытая админ-панель на `/admin` с товарами, остатками автовыдачи,
  покупателями, балансами, покупками и статистикой;
- PostgreSQL-хранилище.

## Запуск на Hostless

1. Загрузите все файлы проекта вместе с папкой `brand-covers`.
2. Установите зависимости: `pip install -r requirements.txt`.
3. Скопируйте `.env.example` в `.env` и укажите настоящий `BOT_TOKEN` от `@BotFather`.
4. Добавьте `DATABASE_URL` PostgreSQL и длинный случайный `ADMIN_SECRET`.
   База создаст таблицы автоматически при первом запуске.
5. При необходимости добавьте ссылки на документы в `WARRANTY_URL`, `TERMS_URL`, `PRIVACY_URL`.
6. Команда запуска: `python bot.py`.

После деплоя откройте `https://ваш-домен/admin` и введите значение
`ADMIN_SECRET`. В панели есть разделы:

- **Обзор** — графики выручки, покупок, посетителей и новых покупателей по дням
  (7 / 30 / 90 дней), динамика к прошлому периоду, статусы заказов, топ товаров
  и категорий, блок «Требует внимания» (оплаченные заказы без товара, закончившиеся
  и заканчивающиеся товары, товары без категории). Данные отдаёт
  `GET /api/admin/analytics?days=30&tz=180`.
- **Товары** — поиск, фильтры, правка цены прямо в таблице, переключатель показа
  в каталоге и карточка по центру: название, описание, категория, автовыдача
  (правка, удаление и массовое добавление позиций) и удаление товара.
- **Категории** — порядок показа и видимость прямо в таблице.
- **Покупатели** — поиск, сортировка, быстрые +5 / +10 USD и пополнение на любую
  сумму по @username или Telegram ID (`POST /api/admin/customers/id/{id}/balance`).
- **Покупки** — фильтры по статусам и поиск по заказам.

Панель обновляется раз в минуту; `/` — поиск, `Esc` — закрыть окно.
При первом запуске в пустую базу добавляются исходные категории: ChatGPT,
Claude, Gemini, Notion, Grok, Perplexity, Netflix, Duolingo, CapCut и Spotify.
Покупатель сначала выбирает категорию, затем товар внутри неё. Примеры
товаров вроде ChatGPT Plus и ChatGPT Pro создаются отдельно через панель;
их цены задаёт владелец магазина.

## Покупка и пополнение через Crypto Bot

1. В `@CryptoBot` отправьте `/pay`, создайте приложение и скопируйте его **Crypto Pay API token**.
   Это не Telegram-токен бота из BotFather.
2. Укажите его в `CRYPTO_PAY_TOKEN` в переменных Hostless, затем перезапустите бота.
3. Для моментального подтверждения включите Webhooks в приложении Crypto Pay.
   Сгенерируйте отдельный случайный `CRYPTO_PAY_WEBHOOK_SECRET` и укажите адрес:
   `https://ваш-домен/api/payments/crypto/<CRYPTO_PAY_WEBHOOK_SECRET>`.
   Без webhook бот проверяет счета через API каждые 30 секунд; также есть кнопка «Проверить оплату».
4. В `/admin` создайте товар, цену в USD и строки в «Автовыдаче»: одна строка — одна единица товара.

**Каталог:** кнопка товара зелёная, если есть свободный остаток, и красная, если товар закончился.

**Карточка товара:** количество выбирается синими кнопками − / +, максимум 100 и не больше остатка.
Плюс и минус — премиум-эмодзи из `https://t.me/addemoji/ABCEmoji`: бот получает их
точные `custom_emoji_id` через Telegram `getStickerSet`, без ручного ввода и подмены
значками другого набора. Если Telegram временно недоступен, остаются рабочие обычные
знаки − / +; загрузка повторяется автоматически, успешный результат кэшируется на сутки.

Внизу карточки — одна зелёная кнопка **«Способы оплаты»**. Она открывает отдельный экран:
общая сумма в USD и рублях, зелёная кнопка Crypto Bot с прямой ссылкой на готовый счёт,
зелёная ссылка на `@Ditzzmback` с текстом заказа и кнопка оплаты с баланса магазина.
Само открытие карточки и изменение количества не создают счёт и не резервируют товар —
резерв появляется только после нажатия «Способы оплаты». Счёт выставляется
на всю выбранную сумму; после подтверждения выдается ровно выбранное количество позиций.
Срок счёта — 10 минут; позиции резервируются с дополнительной минутой на подтверждение оплаты. При изменении количества
старый счёт проверяется и удаляется через Crypto Pay перед созданием нового.

**Кошелёк:** выберите сумму или введите её вручную (0.01–10 000 USD, до двух знаков).
Обе кнопки оплаты зелёные. Crypto Bot открывает счёт и автоматически зачисляет оплату
на баланс магазина. При оплате через администратора зачисление выполняет администратор
через существующий раздел «Покупатели» — одна ссылка не подтверждает оплату.

Подпись webhook проверяется по исходному телу запроса. Перед зачислением проверяются
ID счёта, USD, сумма и сохранённый уникальный payload. Финансовые изменения, отметка
заказа и выдача склада выполняются в транзакции PostgreSQL. Повторные проверки и
повторные webhook не зачисляют деньги и не выдают новые позиции второй раз.
Пополнения учитываются отдельно и не увеличивают выручку от продаж.

Выдача хранится в очереди PostgreSQL: если Telegram недоступен, бот повторяет отправку
тех же позиций после восстановления. При обрыве связи после успешной отправки, но до
подтверждения Telegram, сообщение может повториться — новых товаров или списаний не будет.
Если оплаченный старый/просроченный счёт нельзя исполнить полностью, вся сумма один раз
зачисляется на баланс магазина; для возврата через платёжную систему покупатель обращается
к администратору. Это не автоматический возврат криптовалюты.

Зарезервированный товар нельзя удалить или заменить его остатки до оплаты/истечения счёта.
Изменение цены в админке не меняет уже выставленный счёт. Старые неоплаченные USD-счета
прошлой версии с корректной привязкой к заказу также проверяются. Уже оплаченная история
не меняется; старые счета в другой валюте не пересчитываются автоматически.

Для тестовой сети используйте `CRYPTO_PAY_TESTNET=true`, токен `@CryptoTestnetBot`
и **отдельную тестовую PostgreSQL**. Нельзя смешивать mainnet и testnet в одной базе:
ID счетов могут совпасть. В production оставьте `CRYPTO_PAY_TESTNET=false`.

Проверка после развёртывания: пополните баланс небольшой суммой и проверьте его через
«Профиль», затем купите тестовый товар и проверьте выдачу. Никому не отправляйте API token
в чат. Не удаляйте базу данных при обновлении — схема расширяется без сброса данных.

## Запуск как App на Hostless

В проекте есть `hostless.yaml`: он фиксирует один экземпляр бота и проверяет
`/health`. Бот одновременно работает с Telegram и отдаёт HTTP-ответ на этом
пути, поэтому успешно проходит проверку App и сохраняет HTTPS-адрес для
будущего Telegram Web App.

Покупатели появляются в базе после первого `/start` или `/menu` в боте.
Раздел «Покупки» и выручка заполняются оплачиваемыми заказами; подключение
конкретного платежного провайдера должно создавать записи в таблице `orders`.

## Валюта и оплата

Все цены, балансы, пополнения, статистика и новые счета Crypto Pay — в **USD**.
Сохранённые цены и балансы не пересчитываются и не изменяются при обновлении.
Старые счета Crypto Pay остаются в своей исходной валюте.

На экране оплаты товара и пополнения кошелька бот показывает сумму в USD и
приблизительный эквивалент в рублях по официальному курсу ЦБ РФ. Показывается
только сумма в рублях, без строки о курсе и его дате. Эквивалент справочный: счёт Crypto Pay по-прежнему выставляется в USD.

Курс берётся из `https://www.cbr.ru/scripts/XML_daily.asp`, кэшируется на час;
одновременные запросы объединяются. При недоступности ЦБ используется последний
успешно полученный курс, если с его получения прошло не более суток, без дополнительных строк о курсе. Если такого курса нет, бот сообщает, что рублёвый
эквивалент временно недоступен, но оплату в USD не блокирует.

## Премиум-эмодзи в товарах через админ-панель

Откройте **Товары → Открыть → Описание → Эмодзи**. Выберите значок в визуальной
панели справа (на телефоне — снизу): он вставится на место курсора без ручного
ввода ID. Сохраните товар. Предпросмотр и карточка товара, которую отправляет бот
покупателю, используют тот же `custom_emoji_id`.

Пробные чат-команды, inline-отправка и ручной секретарь удалены. Бот остаётся
магазином; доступ к личным диалогам для его работы не нужен. Если экспериментальные
режимы были включены, отключите подключение в **Настройки → Автоматизация чатов**.
В BotFather можно выключить Secretary Mode и inline-режим (`/setinline` → бот →
`/empty`). Это настройки Telegram; удаление кода само по себе их не переключает.
Неиспользуемую переменную `PUBLIC_BASE_URL` можно убрать из окружения.

Таблицы метаданных секретаря, если успели создаться в предыдущей версии, больше
не используются. Обновление не удаляет их и не меняет данные товаров, покупателей,
балансов или заказов.

## Интерфейс и совместимость

- Отдельный раздел «Эмодзи» в меню убран. В редакторе товара кнопка «Эмодзи»
  открывает визуальную панель справа (на телефоне — снизу). Выбранный значок
  вставляется в описание на место курсора, без ручного ввода ID.
- Вставка сохраняет оригинальный `custom_emoji_id` в `tg-emoji`; предпросмотр
  карточки и итоговый текст бота используют тот же идентификатор. Настройки
  исходных логотипов категорий и значков бота сохранены.
- Каталог наборов загружается только при открытии панели; используется
  существующий `catalog/emojis.json`, исходный порядок наборов сохранён.
  Показываются настоящие статичные миниатюры Telegram. Если миниатюра недоступна,
  значок нельзя выбрать, чтобы не подменять его обычным Unicode-эмодзи.
- Полосы прокрутки и стрелки числовых полей скрыты. Прокрутка мышью, касанием и
  клавиатурой остаётся доступной. Цвета, стеклянные карточки и композиция сохранены.
- Панель загружает данные нужного раздела вместо всех разделов сразу;
  одновременные одинаковые GET-запросы и обновления объединяются.
  Поиск товаров выполняется с короткой задержкой, форматирование чисел и дат
  использует повторно созданные форматтеры.

Проверки кода: `python -m unittest discover -s tests -v`,
`node --test tests/test_admin.cjs` и `node --check admin.js`.

Транзакционные тесты платежей используют только отдельную тестовую базу:

```bash
TEST_DATABASE_URL=postgresql://test_user:test_password@localhost:5432/store_test python -m unittest discover -s tests -v
```

Каждый тест создаёт и удаляет собственную схему. Пользователю тестовой базы нужны права
CREATE SCHEMA. Без `TEST_DATABASE_URL` эти тесты пропускаются; остальные выполняются.
Тесты не обращаются к реальному Crypto Pay и не списывают деньги.

## Реферальный бонус

В разделе **«Бонус»** показывается персональная ссылка
`https://t.me/wanderersshop_bot?start=ref_<Telegram-ID>`, количество приглашённых
и заработанная сумма. Ссылку можно скопировать или отправить другу кнопками.

При первом `/start` нового пользователя по этой ссылке сохраняется пригласивший.
Повторный `/start`, ссылка от самого себя, неизвестный пригласивший и ссылка для
уже зарегистрированного пользователя не меняют привязку.

Пригласивший получает **5% от первой успешной покупки товара** друга на баланс
магазина в USD. Оплата через Crypto Bot и с баланса учитываются одинаково.
Пополнения кошелька, отменённые счета и оплаты без выдачи товара бонус не дают.
Бонус считается от общей суммы первой покупки, округляется до центов и начисляется
в той же транзакции, что и выдача товара; повторные webhook не начисляют его заново.
Если округление даёт 0.00 USD, первая покупка всё равно считается использованной.
В профиле отображается реальное количество рефералов и успешных покупок.
